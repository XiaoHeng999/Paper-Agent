# Paper-Agent 改进总记录

本文汇总本项目从原有串行多 Agent 综述流程，到当前以证据为中心的论文判断工作台的改进，包括中途纠偏、已实现能力、审查发现的问题、修复结果和验证边界。

记录范围：此前架构讨论与实施，以及最近一轮深度审查修复。各阶段按实施顺序整理，不虚构独立提交时间。最后一轮完整验证为 **149 项测试：145 项通过，4 项真实服务测试按环境开关跳过**。

## 1. 产品核心如何变化

以前的主流程更偏向“搜索论文，然后生成综述”。现在的核心产物是可以回查和修订的研究判断：

```text
论文来源
  → 原文证据与位置
  → 主张、成立前提、方法、实验条件和局限
  → 主张核查与待验证挑战
  → 可选的跨论文关系
  → 独立报告、比较报告或综述
```

综述是这些对象的一种交付形式。单篇论文可以独立阅读、核查并生成报告，多篇论文也可以逐篇独立处理。论文数量增加不会自动授予跨篇分析权限。

| 用户需要 | 当前处理 |
| --- | --- |
| 快速理解一篇论文 | 生成判断卡，记录问题、方法、结果、前提、局限与来源 |
| 判断作者结论是否有依据 | 区分忠实转述、实验支持和内部反证，保留核查理由 |
| 比较两篇论文 | 先对齐问题与实验条件，再分析支持、冲突、同质、扩展或条件差异 |
| 写综述 | 使用已核查主张和关系生成段落，再逐段核查 |
| 修正系统理解 | 创建新的判断版本，更新相关核查、关系和正文，保留历史记录 |
| 评价论文 | 提供有证据的分维度观察；用户指定目标及权重后才计算总分 |

`verified` 仅表示本次允许范围内的来源支持相应判断，不代表独立复现、领域新颖性认证或专家共识。

## 2. 第一阶段：重构多 Agent 的拆分和交接

### 原来的问题

旧流程把阅读、分析、大纲与写作串联起来，容易把“工作步骤”直接等同于“独立 Agent”。用户关注的两个风险是：是否有必要拆分，以及下游是否只能依赖上游压缩后的总结。

### 已完成的调整

图节点收敛为检索、来源准备、研究和回复。指定论文可以跳过检索，恢复研究阶段可以跳过已完成的来源准备。

| 角色或步骤 | 当前职责 | 保留理由 |
| --- | --- | --- |
| Search / 检索规划 | 形成检索策略，调用真实论文检索服务 | 输入和工具与论文核查不同 |
| 来源准备 | 下载、解析、分块及缓存检查 | 普通程序，不需要新增 Agent |
| Paper Reader | 在单篇范围内分批读取原文、形成主张 | 多篇可以并行，上下文按论文隔离 |
| Evidence Verifier | 回查来源、检查前提及支持程度 | 核查责任与生成责任不同 |
| Cross-paper Analyst | 对齐两个主张的条件并判断关系 | 只有用户允许跨篇时才需要 |
| Writer | 根据已核查对象生成正文 | 综述模式按需执行 |
| 调度、存储、评分汇总、报告拼接 | 执行确定性规则 | 普通程序完成，不再包装为常驻 Agent |

交接对象包括 `EvidenceSpan`、`Claim`、`AnalysisRelation`、`VerificationResult` 和 `ReportParagraph`。它们保存标识、版本、证据引用及核查状态。

各角色不共享聊天历史；每次模型调用根据论文范围重新装配上下文。下游能够按证据 ID 回取原文，不必仅相信上游摘要。结构化抽取和有限上下文本身仍可能遗漏信息，因此不能把这一设计描述为“完全没有信息损失”。这些角色也主要共用同一研究模型，独立调用不等于多个独立专家。

实现入口：[研究工作流](../src/research/workflow.py)、[模型任务](../src/research/agents.py)、[范围读取](../src/research/context.py)。

## 3. 第二阶段：让单篇路径完整，跨篇路径可选

新增或接通四种输出模式：`paper_cards`、`paper_report`、`comparison`、`review`，另用 `cross_paper_enabled` 表达是否允许跨篇分析。

- 默认逐篇独立报告，跨篇关闭。
- 只有跨篇开启且至少两篇论文有可用主张时，才执行关系分析。
- 要求比较但资料不足时，交付逐篇报告并解释降级原因。
- 禁止跨篇时，检索、证据装配和核查都不得借用其他论文补全判断。
- 恢复请求保留原始范围，不能利用 checkpoint 悄悄覆盖“禁止跨篇”等约束。
- 显式指定的同名不同论文按标识保留，不以标题误去重。

前端同步增加报告模式、跨篇许可、外部补搜许可及评分目标等选项。指定论文列表目前仍主要由 API 提供。

## 4. 第三阶段：清理旧代码，并纠正误删边界

这轮曾把旧 Agent 流程清理扩大到向量入库等能力。用户指出后，重新检查了基础设施与旧编排之间的区别，并恢复、补接了需要保留的部分。

| 类别 | 最终处理 |
| --- | --- |
| ChromaDB、embedding 配置、原有向量存取与入库能力 | 保留并接入新研究流程 |
| 下载、PDF/HTML 解析、分块、缓存、会话、SSE、恢复和取消 | 保留并修复相关边界 |
| 真实工具接口与论文搜索封装 | 保留，按实际工具范围使用 |
| 旧 Analyse / Outline / Writing Agent 及旧图节点 | 删除，由新研究对象和模型任务替代 |
| 旧固定六字段 extraction / verify_extraction | 删除，替换为版本化主张、原文证据及核查循环 |
| 无生产调用的 AgentRegistry / SkillRegistry / AgentEnvironment 空壳 | 删除 |
| 旧专用测试、提示词、阶段映射及停用分支 | 删除或改为新流程测试 |

Chroma 中的向量负责寻找候选证据，不充当事实本身。查询按论文和来源版本限制，结果重新映射到当前原文对象；模型及向量维度使用独立集合。未配置 embedding、入库失败或召回超时会显式降级到原文阅读。

清理原则是：**删除被替代的旧多 Agent 逻辑，保留仍有意义的基础设施。** 历史论文缓存和研究产物没有随代码清理删除。

详细依据见 [架构清理复核](./architecture-cleanup-audit.md)。

## 5. 第四阶段：补齐原文完整性与工程可靠性

| 发现的问题 | 修复 |
| --- | --- |
| 预处理丢弃摘要、参考文献之后的附录等内容 | 保留来源段落，取消有损清理 |
| 只要缓存文件存在就复用 | PDF/HTML → Markdown、Markdown → 分块分别校验来源与策略版本 |
| 分块文件更新可能留下不完整内容 | 使用原子替换写入 |
| 不同论文 ID 规范化后可能撞文件名 | 不安全或被修改的标识增加哈希后缀 |
| 跨篇核查只引用一篇也能通过 | 通过状态必须覆盖目标涉及的全部论文 |
| 没通过核查的写作仍进入正式正文 | 正式正文只接受 verified 段落，其他草稿单独标记 |
| 单篇原文损坏拖垮整批任务 | 当前论文记录错误，其他论文继续处理；来源运行中变化则拒绝不一致快照 |
| Provider 生命周期不明确 | 节点关闭自己创建的连接，注入对象由调用方管理 |
| 恢复字段残留旧评分含义 | 按实际字段类型恢复，并增加较大分块数量测试 |

使用 `uv` 管理 Python 环境和锁文件。后续接入视觉渲染时增加 PDFium 与 Pillow 依赖。当前环境同步与验证命令见 [开发环境说明](./development-environment.md)。

## 6. 第五阶段：从摘要整理扩展到条件分析和批判核查

### 6.1 主张与比较条件

`Claim.study` 记录研究问题、机制、任务、数据集、基线、指标、预算、样本量、消融、负面结果和实现信息。未知内容保留为 `unknown`，不把“未报告”写成“不存在”。

跨篇关系按八个轴记录左右条件及来源：问题、任务、方法、数据、基线、指标、预算、范围。缺少关键条件时，不接受强关系；条件不同不能直接判为冲突，相似措辞也不能直接判为同质。

### 6.2 分项核查与挑战

核查拆为三部分：

- `fidelity`：是否忠实表达原文。
- `experimental_support`：实验是否充分支持当前判断。
- `counterevidence`：当前范围内是否存在挑战判断的反证。

Verifier 在允许范围内扫描限制、失败、消融等原文并补充语义召回。没有找到反证时记 unknown，不等于“没有反例”。系统推论与作者报告分别处理，摘要不能被当作全文实验核查。

当前还记录具体挑战的前提、替代解释、所需验证及证据引用。挑战是待检查的问题，不自动等于已经找到反证。

### 6.3 评价、展示与人工修订

实现五维评价：证据充分性、比较公平性、方法增量、复现透明度、适用范围清晰度。缺信息记 unknown；只有明确评分目标和权重，且所需维度有值，才计算加权分。

网页显示判断卡、维度评价、跨篇关系图、比较矩阵、原文证据和人工修订入口。修订校验报告 ID、主张 ID、版本及证据范围，生成新报告而不覆盖原始记录。

外部补搜需要同时允许跨篇和外部检索，使用现有检索/下载服务，一次最多补入 1–3 篇候选，不形成无限搜索循环。

设计与接口见 [对抗与多论文分析](./adversarial-multi-paper-analysis.md)。

第一版已经形成可执行流程，但工程测试通过不能证明判断质量达到研究产品要求。随后再次深度审查，发现并复现了下一节的问题。

## 8. 第七阶段：深度审查与本轮修复

### 8.1 新增未读页面绕过缓存失效

曾通过实际工作流复现：论文 A 从一页扫描 PDF 变成两页，第一页不变；视觉预算只允许读一页；修订论文 B 后，A 的新视觉记录显示第二页未读，但旧判断卡仍被复用，遗漏列表仍为空。

修复后，`source_manifests` 同时保存原文件/Markdown 指纹、证据版本、读取覆盖与失败状态。文档或覆盖变化会使相关研究对象失效；不变页面的转录仍可复用。修订目标的原文件变化会拒绝陈旧修订，缺少来源指纹的旧 PDF 报告需先重新分析。

核查规则、提示词及关键实现文件内容也参与执行策略指纹，避免规则修改后沿用旧结论。

### 8.2 视觉输入不等于完成视觉核查

- 根据图像对象面积识别带可搜索页眉的混合扫描页。
- 根据问题中的图表编号提高对应候选页优先级，并为后续论文保留预算。
- 将正文中的图表引用映射到实际图注页，减少只检查引用所在页的错误。
- 强制输出 `visual_observations`：论文、页码、图像版本、图表或单元格位置、观察、数值、单位、条件和状态。
- 已提供图片但缺少观察，或原图不清楚，不能 verified；引用未提供原图直接拒绝。
- 网页和报告显示具体观察，扫描转录明确标识为转录。

### 8.3 跨篇分析没有进入写作

Writer 现在接收通过核查的关系、比较条件和未决问题。比较段必须引用关系 ID 及双方主张，段落核查也取得所引用关系。

段落依赖包含相关关系上下文及核查版本。关系改变、消失或新增会让相关段落失效，独立段落仍可复用。部分关系因预算未进入通过核查的正文时，报告明确提示，完整结果保留在比较矩阵中。

这也修正了一个旧测试预期：修改一条主张后，不一定只重写一段。其他段落如果参考了受影响的关系，也必须更新。

### 8.4 跨分块前提、重复主张和评分对象

Reader 为同篇的前提和限制原文预留上下文，显式记录未完成片段；达到输出条数上限时标记潜在遗漏。完整单个片段仍可占满上下文预算，不因预留空间而无法读取。

只合并语义字段完全一致的主张，并合并证据后重新核查；前提不同的主张不能因措辞相似被合并。

评分改为针对适用对象：实验支持和比较公平看结果，方法增量看方法，复现看方法与结果，适用范围看方法、结果、前提和局限。研究问题类主张不再无关地阻止复现评分；原文未读完整仍阻止完整论文评分。

### 8.5 比较预算和反证补搜

候选对按问题、任务、数据、指标和机制匹配程度排序，再在不同论文对之间轮转，避免前几篇耗尽比较预算。未知或字符串不匹配不会直接被当成语义无关而删除。综述模式为写作保留部分调用预算。

外部补搜移动到已有论文的单篇核查之后，围绕实际主张的前提、替代解释和待验证实验形成查询。无实验支持时可形成明确标识的待核查问题。调用预算耗尽时不继续下载无法分析的新论文。

### 8.6 评测无法识别“总回答不知道”

新增标签分布、缺失类别、恒定回避基线、明确结论准确率和不必要回避统计。

新增 **9 个受控合成样例**，覆盖六类关系及实验支持的 supported / contradicted / unknown。恒定回答 unknown / incomparable 在其中 7 个需要明确回答的标签上全部失败。

真实论文、受控合成案例、专家共识分别报告，不能混用成绩。真实论文仍为 4 篇、9 个待审样例，专家标注仍为 0，真实集合覆盖不平衡也会被明确报告。

新增 `run-workflow` 从来源片段开始运行 Reader、Verifier、可选比较和 Writer，不把参考主张或答案提供给 Reader。该输出尚需人工对齐，因此语义准确率为 null，禁止直接当作逐主张评测成绩。

当前完整研究产物为 `schema_version=4`。详细配置、运行命令和各项边界见 [视觉、评测与增量说明](./visual-evaluation-incremental.md)。

## 10. 当前仍未完成或不能保证的事项

- 完整真实论文的专家标注和代表性评测，真实模型的学术准确率及评分校准。
- 对所有跨分块前提、复杂图表和混合版式的完整识别；当前补入与定位仍包含启发式规则。
- 来源内容的自动实验复现、整个领域的新颖性认证。
- 任意文件变化自动触发研究更新、跨会话缓存合并等通用增量调度；当前主要入口是人工修订。
- 长期历史向量索引的垃圾回收。
- 对模型观察是否真实正确的完全自动判定；结构化记录只是让判断更容易被检查。

不因这些限制恢复强制的旧多 Agent 流水线。后续优先方向仍是完善来源与判断的可信关系、扩大真实评测，并以实际收益决定是否需要新增角色。

## 11. 用读书小组解释前后变化

以前，读书小组容易出现“书换了版本还用旧笔记”“看过图就算检查过”“比较的人发现矛盾，写报告的人不知道”的问题。

现在，每张笔记标明书的版本、引用位置、成立条件和检查状态；书多一页时会重新判断哪些笔记过期；看图要写出具体观察；比较结果交给写报告的人，并记录哪些段落依赖它。完全无关的笔记继续复用，需要更新的内容重新检查。

老师出题也不能只有“资料不足”一种答案，所以测试增加了明确支持和明确反驳的场景。但练习题成绩仍不能冒充真实专家考试成绩。
