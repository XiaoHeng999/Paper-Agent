# 从论文拆解到有依据的研究见解

## 当前行为（schema 5）

报告以主论文的关键论证为中心，默认执行结构化论证、研究综合和独立论证核查三个有界模型步骤。它们是现有研究工作流中的函数调用，不增加长期对话式 agent，也不以压缩聊天摘要交接证据。

单篇原文核验仍只读当前论文。外部补证是另一条显式授权的分支，与多论文比较解耦：

| 设置 | 行为 |
| --- | --- |
| `allow_external_search=false`, `cross_paper_enabled=false` | 严格单篇：形成论证和 insight，缺少外部证据就保留未知 |
| `allow_external_search=true`, `cross_paper_enabled=false` | 单篇主导、按需补证：主论文判断卡保持独立，外部候选只进入相关论证，不运行两两比较 |
| `cross_paper_enabled=true` | 另外运行原有跨篇主张比较；是否补搜仍由 `allow_external_search` 独立控制 |

`research_reasoning_enabled` 默认为 `true`。设为 `false` 可运行原有判断卡/比较流程。旧报告可以读取；未有新版字段时界面不展示论证区域。

## 流程与产物

1. Reader 抽取主张，Verifier 区分忠实转述、实验支持和内部反证。
2. `argument_builder` 从当前可提供原文的主张中选择关键问题，每篇最多 4 条论证。每条包含主张、原文证据、推理桥梁、条件、替代解释、证伪条件、当前结论。
3. 只为会改变结论、且需要外部研究才能回答的缺口创建问题；记录查询语句、重要性和停止标准。当前论文未读完本身不是外部补搜理由。
4. 已授权且存在缺口时，先对最多 3 个问题各做一次本文定向核查，仅对仍需外证的问题各查询一次。使用既有检索、下载、解析服务，论文数量默认 2、可设 1–3，受 60 秒及研究总时限约束。下载失败只保留摘要候选，来源错误显式记录。预算停止不表示缺口已经解决。
5. `research_synthesis` 读取主论文与关联候选的原文，更新论证，逐条说明外部证据的贡献和可比条件；最多生成 4 条 insight，不强制凑数。外部候选不会自动变成佐证。
6. `reasoning_verifier` 独立核查每条论证、外部佐证与 insight。漏核对象、越界引用和重复核查会阻止发布通过状态；草稿和失败理由保留供审查。
7. Markdown 和网页先展示论证与 insight，再展示判断卡、评价和细节。证据按钮读取原始证据对象。

`research_state` 新增 `primary_paper_ids`、`argument_plans`、`research_questions`、`reasoning`；另保存独立 `research_reasoning` 产物。论文/主张/证据 ID 不变。给模型的引用临时映射为 C1/E1 等短编号，返回后严格还原、再校验范围；不是模糊匹配，也不改变原文。

## Insight 的约束

- `kind`：机制洞察、边界洞察、研究方向。
- `epistemic_status`：证据支持的推论、待检验假设、研究建议。
- 必须绑定主张和论证索引，保存推导、证据、不确定性、能区分替代解释的具体实验、预期观察以及会削弱判断的观察。
- 假设通过核查只表示推导有依据、值得验证，不表示假设已被证实。
- 摘要级证据不能升级成完整验证；依赖的主论文判断未通过时，论证及“已支持推论”最多为需限定状态。
- 需要比较条件才能解释的不同结果、相容的阶段描述和数字舍入，不能直接宣称矛盾。

当前是文本论证核查，原图核查仍由既有 Verifier 负责。外部文献下载成功不等于实验已复现，全部自动核查也不等于专家标注准确率评测。

## 预算与增量更新

为论证规划、综合及核查预留模型调用数（每篇目标 3 次，上限为总调用预算的四分之一）和时间（较长任务最多 120 秒、总时限的四分之一）。所有调用仍共享全局计数和截止时间。极小预算不能保证每个阶段执行，保留不可用状态，不伪造内容。

论证计划的复用绑定完整判断卡、来源指纹和执行策略。综合结果绑定计划、主张版本、核查状态、关联来源指纹及全部可用证据版本。仅独立核查完成且依赖完全相同时复用；新增或变化的证据会使结果失效。未受影响的论文仍可复用结果。

## 面向学生和科研读者的三项改进

1. **优先交付核心论证。** 先围绕读者的问题选择两到三个关键问题。每次先阅读一个问题、回到原文核查、写明推理和局限，再保存并展示结果，之后才扩大覆盖面。阅读与审查交接主张和原文索引，保留定位到页码、图表或段落的能力。主要指标是从开始运行到第一条带证据、经过审查的论证所用的时间。预算耗尽时应仍可读取已完成的部分。
2. **说明结论能引用到什么程度。** 对关键主张同时给出可引用的表述、决定其含义的原文位置、成立所需的比较条件。例如系统整体加速和单项优化的增量加速使用不同基线。评估时让读者复述结论，检查基线、指标和适用范围是否保留。
3. **让洞见带有可检验的预测。** 标明假设、可能推翻它的观察和可执行的区分实验。先查本文；证据缺口会改变判断且允许外查时，再按问题、可比条件和停止条件调用搜索。外部论文应能追溯到具体主张，注明支持、削弱或因条件不同无法判断。

实施顺序以第一项为先。后两项作为后续产品验收方向。

### 第一项的运行方式

开启研究论证的首次阅读会在每篇主论文首个有主张的阅读批次中，结合用户问题选出最多两个不同问题。该批次优先纳入检索命中、开篇和实验章节的证据。核心问题逐个进入主张核查、论证构建和独立论证审查，随后才核查该批次的次要主张。这个顺序在每篇论文内部生效，多篇论文仍共享总调用预算。

每完成一次独立论证审查，会话立即保存带原文定位和摘录的 Markdown，工作区的输出结果显示问题标题。审查可以给出支持、需限定或证据不支持三种结果。结构化报告在 `core_reviews` 中保留当时的主张版本，在 `first_core_review_seconds` 中记录从研究节点开始到首条审查完成的秒数。后续修订若改变主张版本，早期产物仍是历史快照。若最终综合未完成，逐篇及汇总报告保留仍对应当前版本的早期审查。

可重复的回归场景见 `test/test_research_reasoning.py`。四次模型调用预算下应保存一条核心论证；次要主张核查触发模拟 HTTP 402 时，两条核心论证应已写入会话。这里测量调度顺序与中断恢复出的可读结果，实际论文上的问题选择质量仍需真实案例评估。

### 第二项的运行方式

每条核心论证可附一条作者结论的转述。读者在核心问题快报、最终报告和会话研究面板中看到相同的三项内容：可独立引用的一句话、限定这句话的决定性原文及其位置、移除限定条件可能造成的误读。比较性结论的转述本身须包含基线、指标和适用范围，便于学生复制到读书笔记时保留原意。

论证构建时拟写转述，现有独立审查步骤结合原文判断语义和实验归因，无需新增模型调用。程序在发布前回查同一主张版本，要求决定性摘录出自主论文全文文本、同时被论证和审查引用，并能逐字定位（容许 PDF 换行）。比较基线和指标须实际出现在句中。仅有摘要、仅有扫描转录、转述未获审查认可或摘录无法定位时，仍可阅读论证，引用状态显示为待核实。历史报告可继续打开。

例如 Sol-Attn 图 7 中，引用 HunyuanVideo 的 5.08 倍时应保留 B200、端到端耗时、完整系统及初始配置基线。若讨论在融合与缓存配置上加入 Sol-Attn 的增量，应以 328.4 秒对 170.6 秒计算，约为 1.93 倍。回归测试用可控的图 7 示例检查保存和拒绝路径；对读者的验收可以让学生仅看转述复述一次，再对照原文检查是否仍能指出比较双方、指标和适用范围。


### 第三项的运行方式

洞见必须说明实验如何操作、假设成立时应观察到什么、观察到什么会削弱它。例如可以提出待检验的假设：Sol-Attn 的补偿误差随块内差异增大。固定选块、稀疏率和计算核，分组比较开启与关闭补偿时的误差；若组间差距并未随块内差异增大，应下调对该解释的信心。这是一项实验设计示例。

外查前的论证计划把待检验假设、比较条件、预测、削弱条件、检索词和停止条件绑定到同一条版本化主张。授权外查后，工作流在主论文范围内检索相关段落，让模型回查原文，记录理由和证据编号。本文已有回答、只能做新实验、核查失败或预算不足时，均不发起该缺口的外查。关闭外查仍能获得单篇洞见。定向核查每个缺口最多增加一次模型调用，每轮最多三个缺口，受全局预算限制。

每份候选记录检索它的缺口编号。多个缺口命中同一篇文章时共享候选。综合与独立核查都收到问题及其比较条件，引用必须匹配候选来源、缺口和主张。报告显示外证增强判断、削弱判断，或因证据不足和条件差异保留判断。仅取得摘要时，当前实现会限制核查等级。没有命中或关系未通过核查时，仍保留预测和实验供读者自行验证。
