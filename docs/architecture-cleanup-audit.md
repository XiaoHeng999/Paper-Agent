# 架构清理复核

清理边界是删除被新设计替代的旧 Agent 编排，基础设施不能仅因暂未被新流程调用就删除。

## 恢复与补接

| 能力 | 处理结果 |
| --- | --- |
| ChromaDB 存取、原有分块入库 API | 恢复模块、依赖、配置及 embedding 并发资源；保留既有数据目录 |
| 新流程向量入库与语义召回 | `research/retrieval.py` 接入研究节点，按论文、来源版本及 embedding 模型隔离；返回原文对象而非信任数据库副本 |
| 工具注册及真实 paper_search 封装 | 恢复 `tools.py`、`default_tools.py` 与导出接口；仅删除抛出 NotImplementedError 的工具占位工厂 |
| Agent 注册、技能、环境容器 | 深度复核确认只有定义和导出，没有生产调用；删除这些空壳及 Context 中的无效字段。真实工具注册与范围选择保留，源文件/运行资源由既有服务管理 |
| 请求类型导入兼容 | 保留 ReviewRequest 导入别名，但统一执行新流程，不恢复旧综述路由 |
| 按 ID 回查原文 | 旧 WritingAgent 的 search_section 能力由 ScopedEvidence.read 承接，增加范围校验 |
| 论文来源与引用 | 报告保存 Claim/EvidenceSpan 引用、页码及论文来源列表；不再靠文本替换猜测引用归属 |
| 下载、解析、分块、会话、恢复、取消和进度 | 保留现有能力；研究节点可恢复入库并复用已保存索引 |

恢复原有依赖锁定版本，避免恢复 ChromaDB 时无关升级依赖。

## 仍删除的内容及替代位置

- AnalyseAgent、WritingOutlineAgent、WritingAgent 及三个旧图节点：由逐篇 Reader、Verifier、可选 Analyst / Writer 替代，不再强制串联大纲写作。
- 旧六字段 extraction / verify_extraction：固定字段传递和旧验证循环由 Claim、EvidenceSpan、版本化 VerificationResult 及受限修订循环替代。原文读取、分块与向量存储未删除。
- 旧六字段专用测试：替换为研究工作流、证据引用、核查失败、修订版本和向量范围测试。
- `src/config/baseAgent.md`：描述旧基类方案的文档由 `multi-agent-architecture.md` 的现行设计取代。
- 旧阶段状态、提示词、显示映射及停用评分注释：仅删除旧流程专属部分。

## 实际接入与限制

有全文且配置了 embedding profile 时自动入库，Reader 用召回顺序安排阅读，Verifier / Analyst 用召回补充证据。关闭跨篇时检索范围仅为当前论文；开启跨篇时限定当前比较的两篇论文。正文核查限定其引用主张涉及的论文。

无 embedding、入库失败、检索超时均保留原文阅读，并显式记录降级原因。单次入库最多 30 秒、单次召回最多 15 秒，同时受研究总时间预算约束；embedding 用量单独记录，不混为生成模型用量。仅有摘要时默认不自动建全文索引。

历史原文版本索引保留，以避免并发运行互相删除；查询只匹配当前版本。长期索引垃圾回收尚未实现。向量召回不能保证找到全部反证，Reader 因此不以 top-k 替代全文覆盖。跨论文关系候选目前仍按主张类别生成，尚未改成向量候选筛选。

验证：全量 87 项测试，83 项通过、4 项真实模型测试按开关跳过。其中 9 项新增测试使用临时 Chroma 或测试替身验证入库、召回、隔离、恢复与故障路径；未验证真实 embedding 服务质量。


## 深度审查结论

产品核心是可追溯的论文判断与核查。检索、解析、索引、范围读取、持久化是共享基础设施；只有输入范围或校验责任不同的模型任务才分角色。默认逐篇报告，跨篇比较与综述写作由任务选项控制，不因论文数量自动开启。

审查覆盖 API/会话输入、恢复请求、图路由、摘要筛选与全文准备、PDF/分块缓存、Chroma 存取、研究角色上下文、核查/修订、报告产物及前端选项。

| 发现 | 修正与依据 |
| --- | --- |
| 分块与备用 PDF 解析器删除摘要、参考文献后的附录 | 保留所有来源段落；删除丢失证据的预处理规则。PDF 转换统一使用解析器，移除重复转换函数 |
| 旧缓存仅按文件存在或块长度复用 | PDF/HTML → Markdown 校验源文件指纹；Markdown → chunk 校验来源、论文及分块策略版本；研究恢复亦检查源文件变化。旧 chunk 自动重建，分块文件原子替换 |
| 文件名规范化可能把不同论文映射到同一目录/产物 | 非原样安全 ID 加哈希后缀；缓存与阅读产物共用规则。保留历史磁盘文件，新任务可重建缓存 |
| 跨篇核查仅引用一方也能 verified | verified 必须引用目标涉及的每篇论文；缺少一方则判证据不足 |
| Writer 被核查否定的段落仍进入综述正文 | 仅 verified 段落进入正文；其他段落进入“未通过核查的写作草稿”，保留版本历史 |
| 恢复现场未在创建运行前校验原始选项 | 服务与图层校验；禁止通过恢复悄悄覆盖禁跨篇等约束，修改范围需新建任务 |
| 指定的同名论文被标题去重 | 显式论文列表按标识校验，保留同名不同论文；自动检索继续去重 |
| 单篇原文损坏使整批研究失败 | 当前论文记录无法读取原因，其他论文继续独立交付 |
| 旧评分函数残留在 chunk_count 恢复分支 | 改为非负整数恢复，新增 400 个分块的回归用例 |
| 检索/摘要模型连接未关闭 | 节点关闭自身创建的 Provider，调用方注入对象仍由调用方负责 |
| 多余 Agent 框架抽象 | 删除无生产调用的 AgentRegistry / SkillRegistry / AgentEnvironment；保留具体工具接口、实际检索及 BaseAgent 输入校验，用 ScopedEvidence 执行论文范围隔离 |

新增 `test_architecture_invariants.py` 覆盖以上边界。全量测试 87 项，83 项通过、4 项真实服务测试跳过；前端 TypeScript 检查及 Vite 构建通过。这轮审查不证明实际模型判断质量；后续对抗分析功能的接入状态以 adversarial-multi-paper-analysis.md 第 7 节为准。

对抗分析功能现已进一步接入：分项核查、五维评价、显式加权分、八轴比较、可点击关系图、人工修订与有界外部补搜。当前全量 105 项测试，101 项通过、4 项真实服务测试跳过；详细范围见对抗分析文档。

## 视觉、评测和增量补齐

新增 `research/visual.py`、`incremental.py`、`evaluation.py`，接入现有工作流，没有新增常驻 Agent 或移除 Chroma 能力。新增 18 项测试；全量共 123 项，119 项通过、4 项按开关跳过；前端类型检查和构建通过。具体流程、缓存失效和人工标注边界见 [实现说明](./visual-evaluation-incremental.md)。
