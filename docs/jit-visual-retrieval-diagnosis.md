# 论文图表检索误差分析

分析对应提交 `96d3054`。目标是区分四种失败：原页目标没有成为候选、候选排序出错、找对图但文字读不出、选入证据包后遗漏必要证据。

## 样本和判分

六篇真实 PDF，共十五个英文外观定位问题。问题和目标图来自开发集，PDF 版本由 SHA-256 固定。十三题另有图内短文字标注。默认链路使用本地 GME-Qwen2-VL-2B，把裁剪与同图图注一起编码。CLIP 使用同一对象边界。首选图命中按规范化图号精确判定，读字通过还要求目标原页版本和目标字符串都匹配。[评测标注](../evaluation/visual-retrieval.json) · [评测程序](../evaluation/visual_retrieval.py)

| 指标 | 结果 | 分母和解释 |
|---|---:|---|
| 目标进入 GME 候选 | 15/15 | 从这些已有可定位目标的开发题出发 |
| GME 首选图命中 | 13/15 | 两道错误的目标都排第二 |
| GME 前两名覆盖 | 15/15 | 12 题各有三个候选，2 题各有两个，1 题仅有一个 |
| CLIP 首选图命中 | 12/15 | 与 GME 同题对照 |
| 纯文本首选图命中 | 5/15 | 全文检索对照，与下文“只编码候选图注”的受限实验不同 |
| GME 定位、原页及文字均通过 | 10/13 | 两题首选图错，一题图对但短文字没有匹配 |

这些题无法估计任意 PDF 的图表发现率，也没有覆盖默认八候选上限被打满的场景。原始端到端评测可以按下列命令运行，每篇分别选择两种后端。

```sh
uv run --locked --extra gme --extra image-retrieval python -m evaluation.visual_retrieval "$PDF" --full-text --read-crops --image-model qwen2-vl
uv run --locked --extra image-retrieval python -m evaluation.visual_retrieval "$PDF" --full-text --read-crops --image-model clip
```

## 两道错题的归因

**ResNet 的误差曲线。** 问题描述两幅并排的小图以及红黄曲线的阶梯式下降。正确图 1 的生产裁剪为 472 × 159 像素，能看见两幅曲线图；框内原生文本也包含 training error 和 test error。GME 给图 3 的网络结构图 0.2264，给图 1 分配 0.2233。CLIP 把图 1 放在第一。只给 GME 图注也能选对，改成只给图像又选错。由原 PDF 将渲染宽高各提高两倍后，图 1 以 0.2176 超过图 3 的 0.2163。实验表明这对候选的相对次序对渲染尺度敏感，提升后领先幅度仍小。不能从余弦分数推导模型出错的概率，也不能据此定位模型内部究竟忽略了哪条曲线。

**DETR 的处理阶段图。** 问题同时要求“各阶段有虚线外框”和“右侧一张照片”。正确图 2（692 × 175 像素）和干扰图 1 都包含流程框及照片。GME 给图 1 分配 0.2247、图 2 分配 0.2042。候选图注取自 PDF 的单行，两者分别以“by combining”和“representation of an”结束，缺少后续描述；仅传图像仍选图 1。两倍渲染也未修复。沿长轴切分重叠局部视图后，图 2 以 0.2153 超过图 1 的 0.2117。这支持“空间条件值得单独检查”的假设，尚不能证明改善来自虚线、照片数量或某个特定图块。

对“哪张图”类问题，当前证据选择把视觉检索第一名设为 anchor。第二名可以作为候选证据，系统在这个定位入口没有逐条件比对两张图后再选 anchor 的步骤。两道错题由此保留了首轮排序的错误。[视觉检索](../src/research/image_retrieval.py) · [证据选择](../src/research/selection.py)

## 同候选消融

固定问题、图号集合及模型版本。分别对同一篇论文所有候选排序。GME 各组沿用相同查询指令。报告首位命中，局部视图与融合分数仅用于本次诊断。

| 编码或排序方法 | 首选命中 | 仍然失败的题 |
|---|---:|---|
| GME，图像＋图注 | 13/15 | ResNet 曲线、DETR 阶段图 |
| GME，只编码图像 | 13/15 | 同上 |
| GME，只编码候选图注 | 11/15 | diagram、bars、skip-connection、stages |
| GME，整图像＋两个重叠局部视图 | 13/15 | ResNet 曲线、bars |
| GME，原 PDF 两倍渲染＋原图注 | 14/15 | DETR 阶段图 |
| GME 与 CLIP 全候选名次融合 | 14/15 | DETR 阶段图 |

局部试验沿长轴取首尾各三分之二，使用纯图模式，分数为整图分数与最高局部分数的算术平均。它修复一道，也损失一道。高分辨率试验从 PDF 重新渲染并映射原裁剪区域。融合试验对同篇每个候选计算两种模型的完整排名，累加两项 `1/(60+rank)`，平局沿用 GME 名次。生产审计仅保存前两名，复现完整名次时需要重算候选得分。两种 14/15 都只比当前方案多命中一道，不能作为新论文上的稳定收益。

## 读字与跨段召回需单独诊断

Transformer 架构图已被 GME 正确定位，评测期望读出 Softmax。其对象内原生文字为空。用现有 Tesseract 多方向流程重读该裁剪，438 × 645、876 × 1290 和 1314 × 1935 三种分辨率都没有匹配到目标字符串。下一项可检验的改动是先检测小文本框、按框识别并记录位置，对照当前整图读字。测试应加入位置邻近的多个标签，以防把别处的同名文字当成命中。[OCR 实现](../src/research/label_ocr.py)

此前 QASPER 的输入是论文全文段落。34 道人工跨章节题中，13 题的候选缺少完整证据组；另有 18 题的候选已找齐且放得下，最后选段仍遗漏。图表定位的 13/15 或 14/15 都不能外推到这条纯文本检索路径。前一组适合比较 BM25 与文本向量召回；后一组应固定候选和字符预算，比较当前选段与按子问题分别选取结果、条件等证据的策略。[跨章节评测](../evaluation/qasper_evidence.py)

## 优化与验收顺序

1. **先验证前两名复核。** 对候选分别检查问题中的可观察条件，如子图数量、虚线边界、照片位置；要求返回原图位置和支持或不确定的依据。离线比较首轮排名、只在双模型不一致时复核、对全部前两名复核。此批 GME 与 CLIP 的首选在 4/15 题上不同，两道 GME 错题均在其中，另外两题 GME 原本就答对。记录纠错数、改错数及实际复核成本。模型分差只可用于分流；本批也有答对题的分差约为 0.003。
2. **按视觉需求比较尺度。** 曲线和小字可尝试高分辨率；强调左右位置、多个阶段的题同时保留整图与局部。以每题新增编码次数、峰值显存、冷启动及热缓存 P95 延迟衡量成本。对无证据显示获益的题型保持单次编码。
3. **改善可用文字。** 给断行图注补全有版面依据的后续行，给低分辨率标签做局部 OCR。分别比较旧图注、完整图注、图注＋局部文字，并检查是否错误吸收正文或相邻图注。精确数字、单位及坐标轴仍需对照来源区域。
4. **按论文留出独立验收集。** 在选择融合权重或阈值之前冻结题目与标注；加入扫描页、多栏、超过八个对象的论文、同主题相似图和中文问题。先审计目标是否被发现、是否进入预算内候选，再报告 Top-1、Top-2、正确定位条件下的读字率、最终引用完整率和延迟。每题保留旧方案与新方案的配对结果，包括新引入的错误。只有留出集上的质量与成本同时可接受，再考虑更换默认策略。
