# 对抗核查与多论文分析设计

> 状态（2026-11-21）：已接入结构化判断、比较轴、独立反证核查、五维评价、可选加权分、关系矩阵/图、人工修订重核查及受限外部补搜。本文第 1～6 节说明设计原则；第 7 节列出实际实现、使用方式与未覆盖边界。

## 1. 目标与分析单位

系统要帮助研究者回答：论文到底主张什么、在什么条件下成立、哪些论文支持或挑战它、哪些看似不同的论文实质相近。分析单位应从“整篇论文的摘要”下沉到**带前提和证据的原子主张**。综述、对照表和批判报告是这些对象的不同呈现方式。

“批判”指检查证据、方法和结论的适用范围，不等于生成负面评价。“打分”用于帮助排序和复核，不应把不同领域的论文压成一个无条件总分。

跨论文分析是可选能力。单篇输入，或用户要求逐篇阅读、不跨篇比较时，直接完成“单篇阅读 → 原文核查 → 独立报告”；多篇输入可以并行生成多份独立报告。只有用户要求跨篇分析、任务允许且至少两篇论文可用时，才启动 Cross-paper Analyst。输出模式与 `cross_paper_enabled` 分别控制，具体路由见 [架构规划](./multi-agent-architecture.md)。

## 2. 单篇论文判断卡

这里的判断卡不同于论文作者的 abstract，也不同于现有 `ReadNote.short_summary`。它记录理解和判断单篇论文需要的条件，也可供后续获准的跨篇分析使用：

| 字段 | 要回答的问题 |
| --- | --- |
| 核心问题与主张 | 论文解决什么问题？具体宣称了什么？ |
| 方法机制 | 真正改变结果的机制是什么？与既有方法差在哪一步？ |
| 成立前提 | 依赖什么任务定义、数据条件、模型规模或资源预算？ |
| 实验设置 | 数据集、基线、指标、样本量、消融及统计方式是什么？ |
| 结果与反例 | 哪些结果支持主张？哪里失败、退化或未报告？ |
| 证据定位 | 每条判断对应哪个原文段落、图表或页码？ |
| 不确定性 | 是论文明确报告、系统推断，还是资料不足？ |

一篇论文可以包含多条 `Claim`；一条 Claim 可以指向多个 `EvidenceSpan`。记录论文版本和解析版本，避免新版论文或 PDF 解析变更后沿用旧判断。对于只有摘要、没有全文的论文，应保留来源等级，并限制它参与细粒度实验比较。旧六字段提取与验证流水线已移除；当前直接从原文形成判断卡并独立核查。

## 3. 跨论文关系如何建立

本节只适用于启用跨篇分析的任务。关闭时不生成关系对象，也不要求关系结果才能交付单篇报告。

先**对齐比较轴**，再判断关系。建议至少对齐：研究问题、任务/场景、方法机制、数据、基线、评价指标、资源预算和结论范围。

| 关系 | 判定条件 |
| --- | --- |
| `equivalent` / 同质 | 核心问题、机制和适用条件实质相同；命名或表述不同不足以构成新方法 |
| `extends` / 扩展 | 继承主要机制，但增加新条件、模块或可验证的能力 |
| `supports` / 支持 | 在可比条件下给出相容结果 |
| `conflicts` / 冲突 | 对同一主张、在足够可比的条件下给出不相容结果 |
| `different_scope` / 条件不同 | 结论看似相反，但任务、数据、指标或预算差异足以解释差别 |
| `incomparable` / 无法比较 | 关键实验条件缺失或研究问题不同 |

关系是**主张对主张**的关系，不应仅由整篇论文标题或 embedding 相似度决定。系统应记录比较轴、差异、支持关系的证据 ID 和未解决问题。识别“换名但本质相同”时，重点比较问题定义与方法机制；识别“观点冲突”时，重点检查实验条件是否真的可比。

## 4. 对抗核查流程

Evidence Verifier 共用一个角色，按任务选择 `paper` 或 `cross_paper` 核查范围。单篇任务核查抽取、报告判断及论文内部论证；跨篇任务额外核查指定关系，不为每种范围新增一个常驻 Agent。关闭跨篇分析后仍执行单篇核查。

对每个高影响主张或重要关系，核查者按顺序执行：

1. **回到原文**：检查引用片段是否真实存在、是否被断章取义；图表与正文不一致时标记出来。
2. **寻找反证**：检查该论文自己的消融、失败案例、局限；只有跨篇分析已启用且允许补搜时，才查外部反例。
3. **核对实验条件**：单篇任务核对文中实验与结论是否相符；跨篇任务额外核对不同论文的指标、基线与资源预算是否可比。
4. **给出状态**：`verified`、`qualified`（需要限定条件）、`insufficient_evidence`、`contradicted` 或 `needs_human_review`。
5. **反馈上游**：单篇 Claim 问题退回 Reader；Relation 问题退回 Analyst；成文歪曲问题退回 Writer。反馈携带对象 ID、版本、证据和具体修订要求。

核查者不能仅复述分析者的摘要；它必须有独立的原文读取路径。不同模型或不同提示词本身并不保证独立，关键是能够检验来源和提出可定位的反例。

核查结果记录 `scope`、对象 ID/版本、证据 ID、结论、理由、未检查项及修订请求。`verified` 表示证据支持当前范围内的判断；“作者报告了某结果”与“实验充分证明该结果”分别核查，不能混成一个通过状态。无法读取来源、只取得摘要或缺少实验细节时，明确记录证据等级与限制。对象修订后旧核查失效；需要限定条件的结论必须落实到新版本并重新核查。

单篇核查只访问当前论文及其关联资料，不自动调用外部反证检索。跨篇核查只访问任务允许且与关系相关的论文；补搜仍需满足授权范围和预算。没有关系对象时跳过关系核查，但不影响单篇报告交付。

## 5. 评分与呈现

不建议先生成单一“论文质量分”。可按研究问题展示分维度判断：

- **证据充分性**：结论是否有对应实验和原文支持。
- **比较公平性**：数据、指标、基线和预算是否可比。
- **方法增量**：相较已有论文的机制变化是否明确且有实验证明。
- **复现透明度**：实现、数据、参数和评价过程是否足够清楚。
- **适用范围清晰度**：作者是否说明成立条件、失败情形和局限。

每个维度同时展示理由、证据位置和 `unknown` 状态；缺少信息不能自动记低分。总分只有在用户明确给出目标和权重时才计算，例如“选择优先复现的论文”与“寻找方法新颖性”应采用不同权重。

单篇报告可评价论文内部的基线公平性及作者报告的增量，但不能据此声称已验证其相对整个领域的新颖性；需要外部比较的维度标记为未开展跨篇核查。报告包含研究问题、核心主张、前提、方法、实验结果、局限、核查状态和可定位证据，即使没有任何关系对象也能独立交付。

界面按任务显示视图：单篇或逐篇模式提供判断卡与独立报告；跨篇模式额外提供论文矩阵及可点击证据的关系图。用户可修正判断；修正应保留记录，并重新核查受影响的报告和已存在的关系。

## 6. 最小落地顺序与验收

1. 从少量全文论文开始，建立 `EvidenceSpan` 与 `Claim`，保留原文定位及来源等级。
2. 生成单篇判断卡，验证前提、实验设置和负面结果的抽取质量，接入独立核查、打回与单篇报告交付。
3. 验证多篇但禁止跨篇时，各论文独立处理并生成报告，跨篇 Agent 不被调用。
4. 再启用可选跨篇分支，在一个具体问题下比较两到五篇论文；人工标注真实冲突、条件差异和同质案例作为验收集，之后扩展受任务范围约束的补搜。
5. 最后让综述写作读取已核查对象，生成可以逐句回查的论述。

验收重点是误判：把不同条件误判为冲突、把术语相近误判为同质、把论文没有报告误写为论文不存在该问题，以及给出无法定位的“证据”。与多 Agent 的交接方式和角色边界的关系见 [多 Agent 架构设计](./multi-agent-architecture.md)。

单篇验收还应覆盖：抽取遗漏限定语、混淆作者主张与系统判断、原文无法访问、核查对象已更新，以及核查工具试图访问其他论文。单篇通过状态不得被解释为完成外部复现、新颖性验证或领域共识核查。


## 7. 当前实现与使用边界

### 7.1 代码与能力对照

| 设计项 | 当前实现 | 边界 |
| --- | --- | --- |
| 判断卡 | Claim.study 记录问题、机制、任务、数据、基线、指标、预算、样本量、消融、负面结果、实现信息；缺失值为 unknown | 抽取仍依赖模型，不保证穷尽全文细节；遗漏原文会显式记录 |
| 条件对齐 | Relation.axes 保存八个轴的左右条件、状态与证据；已知轴必须引用双方原文 | 研究问题不同判 incomparable；关键轴缺失不接受强关系；适用条件不同不当冲突 |
| 同质/冲突 | 不用 embedding 相似度直接定关系；同质要求问题、任务、机制及范围对齐，冲突要求数据、基线、指标、预算等可比 | 只取得摘要时不认证细粒度实验冲突、支持或方法同质 |
| 独立反证 | Verifier 从当前范围原文中独立扫描失败、局限、消融等片段，并用受限语义召回补充 | 只找到候选片段不等于找到反证；没有找到反证时是 unknown，不是“没有反例”；未读证据列表保留 |
| 分项核查 | fidelity、experimental_support、counterevidence 分开记录理由、状态和证据 | 忠实复述作者结果不代表实验充分支持；系统推论必须有实验支持才可通过 |
| 维度评价 | Verifier 给出五维 0–4 / unknown 及证据；由普通程序汇总，不新增评分 Agent | 仅针对论文内部已审证据；没有完成实验充分性判断时证据充分性分值为 unknown；不认证领域新颖性 |
| 加权分 | 用户提供 scoring_goal 和 score_weights 后才计算 | 任一指定维度 unknown 时不计算，不按零分或偷偷重新分配权重 |
| 展示 | 网页显示独立判断卡、五维表；跨篇启用后显示主张关系图和比较矩阵，点击查看原文 | 超过 60 个主张使用矩阵避免图拥挤；支持/扩展边有方向；每条边同时显示核查状态 |
| 人工修订 | 按报告 ID、判断 ID 和版本校验，创建新运行并重核查；旧报告、修订理由、依赖失效列表保留 | 来源已变化或越界引用会拒绝修订；仅重核查变化主张和受影响候选关系/段落；按完整来源版本与执行策略复用无关对象，详情见第 8 节 |
| 外部补搜 | 仅 cross_paper_enabled=true 且 allow_external_search=true 时启用，使用现有检索/下载/解析服务 | 当前在单篇核查后，围绕具体主张的前提/替代解释/待验证实验执行一次受限补搜，默认最多 2 篇、最多 3 篇，60 秒且受研究总时限约束；不是自动无限扩张的搜索循环 |

相关代码：`src/research/models.py`、`agents.py`、`context.py`、`assessment.py`、`supplement.py`、`workflow.py`；人工修订 API 位于 `src/services/research.py`；前端为 `ResearchPanel.vue`。

### 7.2 评分规则

0 表示已有明确证据显示严重问题，1 表示弱，2 表示部分充分，3 表示较充分，4 表示当前已审证据充分。缺失信息一律为 unknown，不能据此给 0。

每条核查可以形成带证据的维度观察；论文维度分仅在所有适用于该维度的当前 Claim 都有已知观察、且阅读没有遗漏时显示，采用保守的最低值，并保留全部观察供复核。否则维度分为 unknown，仍显示已有理由及覆盖数量。这里衡量的是“当前证据下的判断”，不表示模型分数已经经过专家校准。

示例：

```json
{
  "output_mode": "comparison",
  "cross_paper_enabled": true,
  "allow_external_search": false,
  "scoring_goal": "选择优先复现的论文",
  "score_weights": {"reproducibility": 3, "scope_clarity": 1}
}
```

这些字段放在 `/api/sessions/{session_key}/runs` 的 `constraints` 中。网页任务选项也提供目标、权重和外部补搜开关。未提供目标与权重时仍显示各维度观察，不显示总分。

### 7.3 人工修订接口

`GET /api/sessions/{session_key}/research` 返回最新研究产物 ID 与完整研究对象。提交修订：

```json
{
  "artifact_id": "最新研究产物 ID",
  "claim_id": "待修订判断 ID",
  "target_version": "该判断的当前版本",
  "reason": "原判断遗漏了数据集限制",
  "changes": {"statement": "在所报告的数据集上有效", "conditions": "仅限文中数据集与预算"}
}
```

发送至 `POST /api/sessions/{session_key}/research/revisions`，返回 202 与新运行的 SSE 地址。可修改 statement、conditions、experiment、study、attribution 和 evidence_ids；证据必须属于该判断的原论文。新版本通过同一个 Verifier，修订不是人工点击后直接变成“已验证”。原始报告仍可下载。

### 7.4 验证与尚未覆盖的能力

离线测试覆盖条件不同误判冲突、问题不同、机制不同、摘要级证据限制、忠实复述与系统推论区分、反证片段读取、评分未知值、显式权重、外部补搜权限/数量/恢复、修订版本与来源失效、跨会话引用拒绝以及 API 路由。

目前全量 105 项测试，101 项通过，4 项真实服务测试按开关跳过；前端 TypeScript 与 Vite 构建通过。测试使用人工构造的条件对齐场景、模型替身和临时数据库，不能代替真实论文专家标注集。这组测试为此前阶段的记录。后续已接入视觉核查、增量调度及真实论文评测工具，见第 8 节。真实学术误判率仍需要实际模型运行和专家标注；领域新颖性认证、自动实验复现不在当前实现范围。
