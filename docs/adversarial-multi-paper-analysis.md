# 对抗核查与多论文分析设计

> 状态：设计提案。当前项目已有单篇阅读、全文六字段提取、提取结果验证和子主题分析；本文描述进一步需要的论文判断卡及跨论文关系层。

## 1. 目标与分析单位

系统要帮助研究者回答：论文到底主张什么、在什么条件下成立、哪些论文支持或挑战它、哪些看似不同的论文实质相近。分析单位应从“整篇论文的摘要”下沉到**带前提和证据的原子主张**。综述、对照表和批判报告是这些对象的不同呈现方式。

“批判”指检查证据、方法和结论的适用范围，不等于生成负面评价。“打分”用于帮助排序和复核，不应把不同领域的论文压成一个无条件总分。

## 2. 单篇论文判断卡

这里的判断卡不同于论文作者的 abstract，也不同于现有 `ReadNote.short_summary`。它记录研究者为了比较论文必须知道的条件：

| 字段 | 要回答的问题 |
| --- | --- |
| 核心问题与主张 | 论文解决什么问题？具体宣称了什么？ |
| 方法机制 | 真正改变结果的机制是什么？与既有方法差在哪一步？ |
| 成立前提 | 依赖什么任务定义、数据条件、模型规模或资源预算？ |
| 实验设置 | 数据集、基线、指标、样本量、消融及统计方式是什么？ |
| 结果与反例 | 哪些结果支持主张？哪里失败、退化或未报告？ |
| 证据定位 | 每条判断对应哪个原文段落、图表或页码？ |
| 不确定性 | 是论文明确报告、系统推断，还是资料不足？ |

一篇论文可以包含多条 `Claim`；一条 Claim 可以指向多个 `EvidenceSpan`。记录论文版本和解析版本，避免新版论文或 PDF 解析变更后沿用旧判断。对于只有摘要、没有全文的论文，应保留来源等级，并限制它参与细粒度实验比较。现有六字段提取和验证可以作为初始材料，但不能直接替代上述判断卡。

## 3. 跨论文关系如何建立

先**对齐比较轴**，再判断关系。建议至少对齐：研究问题、任务/场景、方法机制、数据、基线、评价指标、资源预算和结论范围。

| 关系 | 判定条件 |
| --- | --- |
| `equivalent` / 同质 | 核心问题、机制和适用条件实质相同；命名或表述不同不足以构成新方法 |
| `extends` / 扩展 | 继承主要机制，但增加新条件、模块或可验证的能力 |
| `supports` / 支持 | 在可比条件下给出相容结果 |
| `conflicts` / 冲突 | 对同一主张、在足够可比的条件下给出不相容结果 |
| `different_scope` / 条件不同 | 结论看似相反，但任务、数据、指标或预算差异足以解释差别 |
| `incomparable` / 无法比较 | 关键实验条件缺失或研究问题不同 |

关系是**主张对主张**的关系，不应仅由整篇论文标题或 embedding 相似度决定。系统应记录比较轴、差异、支持关系的证据 ID 和未解决问题。识别“换名但本质相同”时，重点比较问题定义与方法机制；识别“观点冲突”时，重点检查实验条件是否真的可比。

## 4. 对抗核查流程

对每个高影响主张或重要关系，核查者按顺序执行：

1. **回到原文**：检查引用片段是否真实存在、是否被断章取义；图表与正文不一致时标记出来。
2. **寻找反证**：优先查论文自己的消融、失败案例、局限，再补搜外部反例。
3. **核对比较条件**：相同指标名称是否对应相同测量方式？基线与资源预算是否一致？
4. **给出状态**：`verified`、`qualified`（需要限定条件）、`insufficient_evidence`、`contradicted` 或 `needs_human_review`。
5. **反馈上游**：退回具体 Claim/Relation，补充原文、改写适用范围或撤回结论。

核查者不能仅复述分析者的摘要；它必须有独立的原文读取路径。不同模型或不同提示词本身并不保证独立，关键是能够检验来源和提出可定位的反例。

## 5. 评分与呈现

不建议先生成单一“论文质量分”。可按研究问题展示分维度判断：

- **证据充分性**：结论是否有对应实验和原文支持。
- **比较公平性**：数据、指标、基线和预算是否可比。
- **方法增量**：相较已有论文的机制变化是否明确且有实验证明。
- **复现透明度**：实现、数据、参数和评价过程是否足够清楚。
- **适用范围清晰度**：作者是否说明成立条件、失败情形和局限。

每个维度同时展示理由、证据位置和 `unknown` 状态；缺少信息不能自动记低分。总分只有在用户明确给出目标和权重时才计算，例如“选择优先复现的论文”与“寻找方法新颖性”应采用不同权重。

界面建议同时提供三种视图：单篇判断卡、按比较轴排列的论文矩阵、可点击证据的主张关系图。用户可修正判断；修正应保留记录，并触发受影响关系的重新核查。

## 6. 最小落地顺序与验收

1. 从少量全文论文开始，建立 `EvidenceSpan` 与 `Claim`，保留原文定位及来源等级。
2. 生成单篇判断卡，先验证前提、实验设置和负面结果的抽取质量。
3. 在一个具体问题下比较两到五篇论文；人工标注真实冲突、条件差异和同质案例作为验收集。
4. 加入独立核查及打回机制，再扩展到更多论文和自动补搜。
5. 最后让综述写作读取已核查对象，生成可以逐句回查的论述。

验收重点是误判：把不同条件误判为冲突、把术语相近误判为同质、把论文没有报告误写为论文不存在该问题，以及给出无法定位的“证据”。与多 Agent 的交接方式和角色边界的关系见 [多 Agent 架构设计](./multi-agent-architecture.md)。
